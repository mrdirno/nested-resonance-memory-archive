# FEniCSx Docker Integration Plan

**Date:** 2025-11-30
**Objective:** Establish a working FEniCSx (DOLFINx) environment for 3D acoustic simulations within the Duality-Zero project.

---

## 1. Rationale
Direct `pip install` of FEniCSx often fails due to complex C++/MPI/PETSc/SLEPc dependencies. Docker provides a robust, isolated, and reproducible environment, minimizing conflicts with the host system or existing Python virtual environments.

## 2. Docker Image Selection
The official FEniCSx project maintains Docker images. We will use the latest stable image.
*   **Image:** `ghcr.io/fenics-project/dolfinx:latest` (or a specific version like `0.7.0`)

## 3. Workflow for FEniCSx Execution

### 3.1 Step 1: Pull the Docker Image
```bash
docker pull ghcr.io/fenics-project/dolfinx:latest
```

### 3.2 Step 2: Run the Docker Container
The container needs to access our project files (e.g., `fabrication/library/TPMS_Anisotropic_Prism_Artifact03/TPMS_Anisotropic_Prism_Optimized.stl`). We achieve this via **volume mounting**.

```bash
docker run -ti --rm \
    -v /Volumes/dual/DUALITY-ZERO-V2:/mnt/DualityZero \
    --name fenicsx_acoustic_sim \
    ghcr.io/fenics-project/dolfinx:latest /bin/bash
```
*   **`-ti`**: Interactive terminal.
*   **`--rm`**: Automatically remove the container when it exits (for cleanup).
*   **`-v /Volumes/dual/DUALITY-ZERO-V2:/mnt/DualityZero`**: Mounts our project root (`/Volumes/dual/DUALITY-ZERO-V2`) into the container at `/mnt/DualityZero`.
*   **`--name fenicsx_acoustic_sim`**: Assigns a readable name.
*   **`/bin/bash`**: Starts a bash shell inside the container.

### 3.3 Step 3: Inside the Container (FEniCSx Operations)
Once inside the container's bash shell:
*   Navigate to our mounted project: `cd /mnt/DualityZero`
*   Execute FEniCSx Python scripts: `python3 fabrication/analysis/fenicsx_acoustic_solver.py` (This script will be developed later).

### 3.4 Step 4: Exit Container
Type `exit` in the container's bash shell.

## 4. Meshing Strategy (GMSH Integration)
FEniCSx often works with meshes generated by external tools. **GMSH** is a popular open-source 3D mesh generator that can read STL files.
*   **Inside Docker:** GMSH is typically pre-installed in FEniCSx Docker images.
*   **Workflow:**
    1.  Develop a `.geo` file (GMSH script) to define physical groups and mesh parameters.
    2.  Use `gmsh -3 our_mesh.geo -o output_mesh.msh` inside the container.
    3.  Load the `.msh` file into FEniCSx: `msh = meshio.read("output_mesh.msh")`.
